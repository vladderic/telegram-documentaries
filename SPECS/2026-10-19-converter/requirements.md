# Requirements — The Converter (Phase 4)

## Goal

Turn the stored portrait photo plus the interview dossier into **one fused
hybrid portrait** and deliver it into the user's Telegram chat.

## Context

- ROADMAP Phase 4: *"Multimodal hybrid portrait: original photo + dossier →
  Gemini Flash Image → portrait sent directly to Telegram."*
- Both inputs already exist:
  - `session.photo_local_path` — the accepted portrait bytes the Bouncer wrote
    under `media_root/<chat_id>/portrait.jpg`;
  - `session.interview.profile` — the typed `BehaviouralProfile`
    (`profile`, `suggested_animal`, `animal_description`).
- **Live recon** (real API call, 2026-10-19) fixed the model and the payload
  shape: `gemini-3.1-flash-image` accepts
  `contents = [{"text": ...}, {"inlineData": {"mimeType": "image/jpeg", ...}}]`
  with `generationConfig = {"responseModalities": ["IMAGE"]}` and answers with
  the fused JPEG in `candidates[0].content.parts[*].inlineData` (~7.6 s,
  ~730 KB). No aspect-ratio configuration is sent (decision 2 below).

## Behaviour

| Event | Behaviour |
|---|---|
| Interview ends (model FINISH **or** the 7-answer ceiling) | Case-file reveal (unchanged), then a short "developing" hold line, then the portrait |
| Portrait generated | Sent with `sendPhoto`, captioned with the species name; session stays `CONVERT` |
| Any message after the portrait | Existing holding reply — no new run (Phase 5 replaces this with the narration) |
| Gemini image call fails / times out / returns no image | Loud log, in-character failure line, session stays `CONVERT`; **no retry** |
| Portrait file missing or unreadable on disk | Same as above, with the reason logged |
| Telegram `sendPhoto` fails | Loud log, in-character line; never raises into the poll loop |

Every failure degrades in character and keeps the session usable — a broken
portrait must never crash the bot or lose the interview.

## Decisions (user, 2026-10-19)

1. **Automatic**: conversion runs as soon as the interview ends — the user does
   nothing extra.
2. **No aspect-ratio config**: the model frames from the photo the user sent
   (one less knob, YAGNI).
3. **No automatic retry** on image failure (cost/latency): degrade in character.
4. The delivered image is **captioned with the species name**
   (`The crew's portrait of you as a {animal}.`).
5. After delivery the session **stays in `CONVERT`**; Phase 5 appends the
   narration to the same run.

## Contracts (typed, at the boundary — TECH.md)

- `GeneratedImage` — the stage's output, ready to upload:
  - `mime_type: str` — must be an image type (`image/jpeg`, `image/png`,
    `image/webp`); anything else is rejected;
  - `data: bytes` — non-empty; the base64 wire form is decoded **at the edge**
    (a `mode="before"` validator), so no base64 ever travels past the boundary.
- `ConverterClient.fuse(portrait: bytes, mime_type: str, profile: BehaviouralProfile) -> GeneratedImage`
  — one model call; raises the shared `GeminiApiError` on transport, HTTP,
  malformed response, or a response with no image part.
- `build_prompt(profile: BehaviouralProfile) -> str` — pure function so the
  prompt is unit-testable without a network call.
- `TelegramClient.send_photo(chat_id, data: bytes, mime_type: str, caption: str) -> Any`
  — `multipart/form-data` POST to `sendPhoto` (`chat_id`, `caption`, file field
  `photo` with a filename derived from the mime type). **Never retried** (a
  double send would post the image twice); the bot token never appears in any
  error message.

## Prompt rules (what the model is told)

- Use the supplied photo as the subject's **real likeness** and keep the face
  recognisably the same person.
- Fuse that likeness with the stated species; the dossier's quirks drive the
  pose, expression and setting.
- One subject only; natural-history film still; shallow depth of field.
- **No** text, captions, watermarks, frames, split-screen or collage.

## Out of scope (YAGNI)

- No video, no multiple variants or user choice of animal, no editing loop or
  regeneration command, no retry queue, no persistence of the generated image
  beyond the Telegram upload, no aspect-ratio or style toggles.

## Privacy

The portrait stays local until this phase; it already travels to Gemini for the
Bouncer, so the Converter adds no new recipient. Generated bytes are never
logged (only sizes and the mime type).
